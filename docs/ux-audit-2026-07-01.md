# Chewabl — Full UI/UX & App Store Readiness Audit
*2026-07-01 · Six-track audit: 5 specialist code reviews (navigation/IA, core loop, visual system, states/a11y, App Store compliance) + a live guest-mode walkthrough of the running app. Target: Apple App Store submission within one month.*

**Verdict: NOT submittable today, but launchable within the month.** The happy path is genuinely delightful and the codebase is disciplined — the gaps are (a) missing launch artifacts, (b) missing social-safety features Apple requires, (c) edge/failure paths in the core loop, and (d) a systemic error-handling weakness. Nothing requires a rewrite.

# ⚠️ MAJOR (likely rejection or visibly broken in week one)

## App Store compliance
- **Unused permissions**: `NSCameraUsageDescription` declared, no camera code (only photo library, `profile/index.tsx:781`) — remove. **Always**-location declared, code is foreground-only (`AppContext.tsx:279,337`) — switch to When-In-Use. Android `RECORD_AUDIO`/`WRITE_CONTACTS` unused.
- **Push entitlement missing** in `ios/` (no `.entitlements`, no `aps-environment`) while token code runs (`services/notifications.ts:41`) — verify EAS credentials add it.
- **Google Places API key inlined in the client binary** — restrict by bundle ID or proxy through backend (also the top cost risk; kill-switch in `infra/` is lagging, not preventive).
- **`NSPrivacyCollectedDataTypes` empty** despite collecting contact info/contacts/location/photos/push token — populate to match the App Privacy label. Note: device contacts' phone numbers are uploaded to `POST /users/lookup` for friend-matching (`friends/index.tsx:198` → `services/friends.ts:44`), matched transiently — declare correctly.
- **Delete-account cascade gaps**: user not `$pull`ed from other plans' `joinRequests[]`; deleted user's identity persists in others' notification `data`.
- **Orientation mismatch**: app.json `portrait` vs native Info.plist listing landscape.
- **Rork dev toolkit in the pipeline** (`metro.config.js` withRorkMetro, start scripts, expo-router origin rork.com) — confirm nothing leaks into prod builds.

## Core loop honesty & dead ends
- **No group re-roll** when everyone hates the winner — top vote always wins even at 1/8 (`group-session.tsx:1214`).
- **False "Perfect Match!"** — `totalMembers=voterCount`, so 2 of 8 voting still celebrates a match (`group-session.tsx:344-348,1039`). Base on eligible participants.
- **Results never explain the win** — rating tie-break + curveball ineligibility invisible (`tallyVotes.ts:32,14-16`); a curveball can win the popular vote and silently not win.
- **Invites are existing-friends-only** — no join code/share link/SMS anywhere (`group-session.tsx:1839-1857`) — throttles the viral loop.
- **"Reserve a Table" + success haptic implies in-app booking**; it's a Maps deep-link (`ReservationSheet.tsx:164,179,133`). Retitle "Find a Table," neutral haptic. Trust landmine.
- **RSVP**: countdown never states the consequence (auto-decline then "You've been removed" push after the fact, `deadlineEnforcer.ts:61`); invitees can't change a mis-tapped response (`plans.ts:699`); auto-confirm can crown a 0-vote winner (`deadlineEnforcer.ts:117-176`).
- **Hosts can't change the restaurant via Edit** (`plan-event.tsx:121` never hydrates pinned).
- **Solo deck exhaustion is a dead end** — Reset re-serves the same set (`swipe.tsx:212`); no first-time swipe coach mark either (`SwipeCard.tsx:96`).
- **Guest dead-ends**: "Plan a Feast"/"Group Chomp" clear guest mode and hard-replace to a backless `/auth` (`(home)/index.tsx:290-312`); guest reaching plan-event gets a permanently disabled CTA (`plan-event.tsx:499,555-558`); friendless users likewise with no explanation (`:1040,1142`). Route all through ConversionPrompt.
- **Plan notifications deep-link to the LIST, not the plan** (`_layout.tsx:101-102` → `plans/index.tsx:52-61` only picks a filter); `id` vs `planId` param mismatch vs join-requests (`notifications.tsx:78,114,128`).
- **Shipped dead button**: group results "Share" fires `Alert('Coming Soon')` (`group-session.tsx:1025`); restaurant Share likewise (`restaurant/[id].tsx:145-147`).

## Resilience (systemic)
- **8 of 11 screens never render `isError`** — failed fetch is indistinguishable from empty (Home, Discover, Friends, Swipe, Notifications, Friend-Plans…). Add inline error + `refetch()` everywhere.
- **Zero offline awareness** — no NetInfo/onlineManager/banner; airplane mode = silent stuck skeletons.
- **"Pull to refresh" copy with no handler** (`friends/index.tsx:241`; FlatLists 405/433/452) — a visible broken promise. Pull-to-refresh missing on 10/11 screens (only notifications has it).
- **Group-session poller swallows errors** (`group-session.tsx:426-428,107-113`) — a blip mid-vote silently freezes state; add "reconnecting…".
- **Raw backend error strings shown in Alerts** (`edit.tsx:133`, `plan-event.tsx:694-696`).
- **Missing back button + timeout on cold-start loading states** (`plan-detail.tsx:1486`, `restaurant/[id].tsx:154`, `friend-plans/[id].tsx:125`) — hung deep-link fetch is unrecoverable.
- **Returning-guest bounce race**: `guestQuery.isLoading` omitted from the composite gate (`AppContext.tsx:594`) — one-line fix.
- **No autofill anywhere**: zero `textContentType`/`autoComplete` on email/password fields (auth, forgot-password, edit) — no Keychain/strong-password/SMS-code support.
- **`profile/edit.tsx` lacks KeyboardAvoidingView** (plain ScrollView:185).

## Visual system / dark mode
- **System dark mode ignored** — app.json says `automatic` but `useColors()` reads only the manual toggle (`ThemeContext.tsx:71-72`); dark-phone users open a light app; native views (keyboard, sheets) mismatch the JS UI. Add `useColorScheme()` default + 3-way System/Light/Dark control (`profile/index.tsx:1034`).
- **No `<StatusBar>` anywhere** — icon color never set per theme; can be invisible in dark mode.
- **`keyboardAppearance` set on zero TextInputs** (auth.tsx:659-812, forgot-password.tsx:529,711, profile/edit.tsx:192-218, delete-account.tsx:233, CodeInput).
- **`review-picks.tsx` has no safe-area handling** (plain View:279, hardcoded paddingBottom:40) — notch collision.
- **Splash background white in both modes** (app.json:14) — dark-mode cold-launch flash.
- **7 visible dark-mode leaks**: friends decline button white circle (`friends/index.tsx:351/646`), notifications loading bg (`notifications.tsx:256`), group-session progress track (`group-session.tsx:875/1469`) + medal number contrast (`:1139`), ConversionPrompt (`:394`) and LockedTabScreen (`:383`) hardcoded light-orange `#E85D3A`, plan-event Switch track static border (`plan-event.tsx:1016`).
- **Duplicated color source of truth** — `constants/colors.ts` is a byte-identical copy of ThemeContext `LIGHT`; will silently desync. Re-export instead.
- **Touch targets pervasively < 44pt without hitSlop** — worst: `filtered-restaurants.tsx:151` back (~20pt), `TimeGrid.tsx:280`, `SortHint.tsx:88`, plus back/close/undo buttons across swipe, group-session (×6), restaurant, plan-detail, notifications, profile/edit, home bell, DecisiveResultView. Standardize a 44pt-min pressable.

## Animation bugs
- **SizzleShimmer re-fires on every FlatList scroll-back** (per-mount `hasAnimated`, `SizzleShimmer.tsx:19,29`) — gate per restaurant id; static shimmer band also renders permanently for reduce-motion users (`:32,52`).
- **NibbleFeedback 100ms timer not cleared + defers pooled event** (`NibbleFeedback.tsx:109`) — double-fire/null-event risk on ~13 surfaces incl. auth.
- **ChompOverlay `isAnimating` can stick true** on mid-animation unmount, blocking all future chomps (`ChompOverlay.tsx:459-468`).

# ✅ THE GOOD (leave alone — this is real quality)
- **Compliance surprises in your favor**: Sign in with Apple NOT required (email/password only); guest mode already satisfies 5.1.1; zero tracking SDKs so no ATT; ATS locked down; PrivacyInfo.xcprivacy present; account deletion is a real server-side hard delete with cascade.
- **No mock/fake data can reach users** — the historical blocker is fully cleared (grep-verified; Places failures degrade to fewer/empty, never fabricated).
- **Empty states are the app's strength** — rich, CTA-driven, per-context (location, no-recs, no-plans, no-friends); per-tab tailored guest conversion screens ("Eat together, on purpose" / "Food is better with friends" / "Your spot for your spots") instead of a generic wall.
- **Reduced-motion respected in ~15 components**; swipe deck has labeled VoiceOver button alternatives (Pass/Choose/Undo).
- **Pre-permission location pattern is textbook** — explain → OS prompt on tap → zip fallback on deny; notifications permission asked contextually on the Profile toggle.
- **Dark-mode discipline ~95%** — the two-level color system is followed nearly everywhere including module-level helpers; palette is a designed warm-neutral ramp, not an inversion; per-mode AA-tuned semantic colors.
- **Nav fundamentals**: no auth flash on cold start; group swipe progress survives app-kill (AsyncStorage + deck fingerprint); deleted-target screens handled; `router.replace` prevents re-entering completed flows; notifications back-fallback is the model pattern.
- **Core mechanics**: real undo with stale-closure guard; decision-ready card hierarchy; deterministic fair tie-break (no RNG, curveballs excluded); ClosedWinnerSheet's reschedule/switch/keep flow is a standout; auth/forgot-password validation is best-in-class (live inline, PasswordChecklist, mapped server errors).
- **Solid API layer**: 15s abort timeout, typed errors, human messages, de-duped 401 handling, offline-cached user.
